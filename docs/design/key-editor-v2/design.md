# 键位编辑器 UI / UX 设计稿

本稿定义方案、草稿与保存的交互契约。当前视觉以 [官方壁纸主题](visual-v3.md) 为准，绑定展示与差异交互见 [按键视图与动作视图](../binding-views.md)。

## 操作模型

**选择方案 → 直接改键或选择快速配置 → 应用更改。**

主界面只保留两个常驻操作按钮：顶部“刷新”、底部“应用更改”。选择方案负责查看和编辑，游戏当前使用哪个方案用单独的“游戏当前”标记表示。

| 控件 | 用户看到的含义 | 行为 |
| --- | --- | --- |
| 三个方案页签 | 默认预设 / 自定义 1 / 自定义 2 | 切换即重新读取磁盘最新数据；选中页签不立即启用方案。 |
| 刷新 | 获取游戏最新设置 | 同时刷新方案选择和键位；保留本地草稿。 |
| 键鼠 / 手柄页签 | 两种设备均编辑当前选中的方案 | 切换方案同时切换键鼠及手柄；有草稿的设备显示小圆点。 |
| 快速配置下拉框 | 用现成配置开始编辑 | 选中后直接更新预览和修改标记，无须再点“套用”；此时不写盘。 |
| 设为游戏当前方案：「自定义 1」 | 决定是否把正在编辑的方案设为游戏使用方案 | 勾选后加入待应用的更改；只有启用意图、没有键位编辑时也能应用。当前已启用方案显示勾选且不可取消。 |
| 应用更改 | 保存当前方案的键鼠、手柄及可选启用项 | 底栏先列出此次范围和修改数；其他方案两种设备的草稿保留，不顺带提交。全局重置时改用下述整组规则；没有变化时禁用。 |
| 撤销更改 | 放弃此次应用范围的草稿 | 仅有未应用修改时出现的次级描边按钮，与应用按钮等高等宽对齐；恢复当前方案两种设备最新读取的磁盘状态。 |

“载入”“自动查找”“套用预设”“保存到存档”“启用该方案”和独立“一键攻防”按钮不再并列出现。自动查找在启动时完成；少用的手动操作进入右上角“更多”菜单。

## 信息层级

1. 暗色窗口标题栏：产品名称与独立的最小化、最大化／还原、关闭；下方品牌区右侧排列语言选择、“刷新”和“更多”。
2. 一行存档位置与游戏运行状态；路径只作说明，不要求用户理解文件名。
3. 三个方案页签；“正在编辑”和“游戏当前”以选中态和徽标分别表达。
4. 设备页签与“快速配置”选择器；选中预设后，用一行短说明展示改动及副作用。
5. 主体为动作与绑定表格。只显示游戏动作名称；三个原有槽位中性命名为“绑定 1 / 绑定 2 / 绑定 3”，不臆测它们的主键或场景含义。内部 `IA_*` 标识收进悬停详情。
6. 底栏：可选启用项、草稿状态、按需出现的撤销操作，以及唯一主按钮。

键位用“左键”“右键”“Shift”等可读名称显示。表格展示实际按键与状态圆点，绑定弹窗的默认选项同时标出具体原厂键；默认继承与明确解绑分开。点击绑定后可录入按键或选择现有键名；清除覆盖同样保留。完整展示规则见 [按键视图与动作视图](../binding-views.md)。共用按键是受支持功能，不以红色冲突提示阻止。

## 刷新与未保存编辑

- 启动自动查找并读取；找不到时就地提供“选择存档”入口，不显示空表格和操作步骤条。
- 切换方案、点击刷新、窗口重新获得焦点时检查磁盘版本；方案切换必须执行最新读取。
- 键鼠和手柄草稿都按方案保存。手柄记录以 `ProfileId` 确定方案，以 `Family` 区分同方案中的设备家族；同为 Xbox 不代表跨方案共用。切换时读取对应方案，不复制到其他方案。外部仅修改其他键位时，刷新最新数据后保留本地编辑，不能整份用旧缓存覆盖。
- 方案页签的草稿标记覆盖键鼠与手柄；只有手柄更改也必须显示。无法归属方案的手柄记录不能猜成共享设置，应保留原数据并明确拒绝不确定范围的写入。
- 外部和本地修改同一绑定时，展示具体冲突，允许逐项选择保留本地或采用游戏值；不得静默丢弃任一方。
- 切换方案时，启用勾选按新方案的真实启用状态重新呈现，不能保留一个看不见的其他方案启用意图。
- 应用前再次检查版本；遇到外部新改动先处理冲突。成功后清除已提交草稿并更新“游戏当前”标记；失败时保留草稿，并准确说明落盘状态。
- 游戏运行时可查看和编辑草稿，应用按钮禁用并就地提示“退出游戏后可应用”。

## 保留功能与说明

| 现有能力 | 新入口 |
| --- | --- |
| 一键攻防 | 快速配置：“左键同时防御（保留右键）”；只增加左键 / 手柄 X 防御，保留右键 / LB 防御及其他已有绑定。 |
| 一键攻防＋闪避冲刺 | 快速配置：“左键攻防＋右键闪避 / 高速移动”。 |
| 魂系手柄、空格高速移动、空格闪避 | 快速配置中的对应选项；展示实际影响的设备。 |
| 清除全部覆盖 | 更多 → 全部恢复默认；先展示涉及全部方案与手柄的范围，确认后加入草稿，最后统一应用。 |
| 自动检测、手动文件选择 | 启动自动检测；更多 → 更换存档 / 重新查找游戏。 |
| 游戏支持的全部界面语言、关于 | 顶部语言选择；更多 → 关于。 |
| 保存前备份 | 应用时自动执行；更多 → 打开备份目录。 |

预设要展示增加和替换范围。一键攻防只增加，保留右键 / LB；“攻防＋闪避”仍明确说明右键 / LB 改为闪避与高速移动。跨键鼠和手柄的预设要同时标记两个设备页签，应用前可逐页查看。若可用绑定已满，不能为新增而静默丢失已有不同绑定，必须保留草稿并提示用户处理。

## 配置预览与全局重置

快速配置是一次可替换的预览。首次选择前记录当前方案键鼠和手柄的草稿检查点；连续切换配置均从该检查点重新计算，不叠加上一次配置。预设只修改目标方案，不能通过遍历全部手柄记录而扩散到其他方案。选择“不使用快速配置”回到检查点。配置未触及的已有手动编辑保留。

手动改键或切换方案会结束本次预览，保留当前结果并将快速配置选择重置为“不使用快速配置”；之后选择配置以当时草稿为新检查点。手动编辑状态由绑定内容与待应用计数表达，不伪装成一个可选配置。说明区明确“仅连续选择时替换预览；手动修改后作为普通草稿保留”。刷新时检查点也随外部修改合并，同键冲突适用相同规则；撤销或成功应用清除相应预览。

“全部恢复默认”先确认“全部方案的键鼠和手柄”，然后形成一个全局重置草稿。底栏持续显示该范围，应用提交全部方案的两种设备，撤销则恢复操作前各方案的草稿（并合并期间读取的外部更新），不丢弃先前编辑。重置待应用时可以查看和刷新，编辑、快速配置与启用选择暂时禁用；先应用或撤销重置。重置不改变游戏当前方案。

应用同时涉及键位和启用项时，先验证两个目标与版本，再保存键位，最后启用方案。若键位已保存但启用失败，明确显示部分成功，清除已保存绑定的草稿、保留待启用意图；重试仅处理剩余项。禁止把部分成功描述为全部失败或全部成功。

## 视觉与验收

采用官方壁纸与深色界面，配色、字体及控件规则见 [官方壁纸主题](visual-v3.md)。不使用巨大快捷按钮、卡片仪表盘或编号步骤条。游戏运行时单独提示应用受限，不用“下次启动”等措辞替代操作含义。

验收应覆盖：直接改键、预设预览后微调、只启用方案、编辑未启用方案、切换后读取游戏新改动、保留草稿、同键冲突、游戏运行、异常写入、手动选择存档和恢复全部默认；全部语言布局仅在针对性本地化测试时检查。设计图需自检按钮数量、方案状态含义、预设副作用和可读性；不得当成已实现软件截图。

首版生成图仅作历史参考；其中“下次启动”和替换右键防御的文字已由本契约修订。当前成品必须以实际程序截图和行为检查验收，静态概念图不能验证切换读取、草稿保留及异常处理。
