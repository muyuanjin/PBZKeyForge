# 键位编辑：按键视图与动作视图

## 目标与范围

PBZKeyForge 同时提供“按键视图 / 动作视图”。两种视图使用同一份绑定状态和编辑草稿，分别从按键与动作两个方向编辑同一份多对多映射。两者都是完整编辑入口，不以复杂程度分层。

按键视图回答“左键、右键、F 各有几个功能，相对原厂增加或移除了哪些功能”；动作视图回答“轻攻击、防御等动作分别绑定了哪些按键”。前者以按钮为中心，并把相对原厂的差异作为主要信息；后者以动作记录为中心，与存档的组织方式一致。

本设计更新 [键位编辑器交互契约](key-editor-v2/design.md) 中的绑定展示部分。方案选择、设备切换、刷新、预览、撤销、冲突处理、应用范围和安全写入继续遵循原契约。

## 默认基准

“默认”须区分两个含义：

| 名称 | 含义 |
| --- | --- |
| 默认预设 | 三套可选方案之一，其当前内容也可能被修改。 |
| 原厂默认 | 游戏为相应方案、设备和映射定义的初始绑定，是比较与恢复的基准。 |

比较基准为**当前所选方案、当前设备对应的原厂默认配置**，不能拿“默认预设”方案当前保存的内容比较，也不能拿本次打开文件时的状态冒充原厂默认。

三套方案共用资源原厂基准，方案中保存的自定义覆盖独立比较。手柄家族记录按动作、原始槽和原厂 `DefaultKey` 匹配，不能跨方案或跨家族借用当前值；缺少对应家族记录时继承该注册槽默认。

原厂数据从 CL-301524 的输入映射资源提取，见 [默认键与无绑定](../input-defaults.md)。`InputDefaults` 保存逐槽注册键及固定映射，动作级集合从这些数据去重生成。游戏主／副列按默认键合并内部映射，不能直接对应编辑器三个逻辑列；逻辑列通过动作自己的槽表定位。

缺失覆盖继承对应注册槽的原厂键，显式 `None` 保持解绑。格挡的键鼠槽 0、2 都默认右键，只修改一个槽仍保留另一个槽提供的右键。已知动作的额外槽默认无绑定；未知动作的默认值显示“未确认”，不以未知值计算原厂一致或恢复结果。

## 按键视图：图形按键与映射功能

### 展示

内容采用两栏：左栏将键盘、鼠标放在同一画布，右栏显示选中按键对应的功能。点击真实按键位置或其数字徽标即可选中，无需展开按键表、切换键鼠子页或启用差异筛选。手柄页使用所选家族的控制器图。

数字徽标位于对应物理按键右上角，数字始终表示当前不同动作的数量。右侧列出当前功能和已移除功能，可添加功能、移除关系、找回关系或恢复该键原厂配置。点击功能打开其按键编辑窗口，可以录入图中没有的新键；已有的图外键以可点击键帽补充，随窗口宽度换行。

鼠标图覆盖左键、右键、中键及侧键 4／5，均可直接点击。F 等键盘绑定在同屏键盘上显示。小窗口中键盘使用画布可用宽度，手柄保持可读尺寸，超出高度时纵向滚动，点击后保留滚动位置。同方案不同家族记录独立选择与编辑。

数量按**不同动作**计算，同一动作在多个内部槽绑定同一个键，只计一个功能。多个动作共用按键是支持能力，不作为冲突阻止保存。完整性按当前键判断：显式存在的关系已确认，原厂集合之外且未显式绑定的键可确认不存在；不能因为某动作的其他槽继承默认就将全部按键标成下限。只有当前键可能受未确认继承影响时才显示 `n+`；未知的零数量显示 `?`。

“左右键攻防”配置的功能展示为：

| 按键 | 功能数量 | 功能列表 |
| --- | --- | --- |
| 鼠标左键 | 2 | 轻攻击、防御 |
| 鼠标右键 | 2 | 重攻击、防御 |
| F | 1 | 重攻击 |

功能列表表达输入映射；组合技能的实际出招结果取决于游戏状态与输入处理，不能额外计入一个未经验证的“鸣剑”动作。

### 数字徽标与关系圆点

| 状态 | 展示方式 |
| --- | --- |
| 灰色数字徽标 | 该键的功能集合与原厂一致。 |
| 蓝色数字徽标 | 已修改并应用，与原厂不同。 |
| 黄色数字徽标 | 该键的功能集合相对修改前发生变化，等待应用。 |
| 灰色关系圆点 | 该键原厂已有的功能。 |
| 蓝色关系圆点 | 相对原厂新增并已应用的功能。 |
| 黄色关系圆点 | 这条具体有效按键—功能关系待应用，不影响同动作的其他按键。 |
| 灰色移除项 | 图标灰化并加斜线、名称灰色删除线，状态文字与圆点也用灰色；保留恢复按钮。 |

徽标颜色优先级为黄、蓝、灰。黄色不改变数字的含义，数字不是改动条数。移除最后一个功能后保留黄色 `0`，应用后为蓝色 `0`。应用把黄色转为蓝色或灰色；撤销按已保存状态恢复。普通未绑定且没有差异的键不显示徽标。

手柄面键与十字键的徽标沿各自按键组向外分布：上键在上方、下键在下方、左键在左侧、右键在右侧。数字徽标和按键本体均可选中，避免徽标挤入按键组中心。LT／RT 将数字输入与轴输入汇总到同一个物理扳机，按不同动作去重计数；编辑仍保留真实输入键名。

状态名称为“原厂一致 / 已修改 / 待应用”，配色参照[状态配色图](binding-status-colors.png)。徽标数字统一使用深色，保证黄色背景上的可读性；待应用的方案、设备圆点与底栏提示也使用黄色。画布底部常显三色图例，悬停徽标可查看按键、动作数及状态。右侧功能用文字与小圆点共同说明状态。原厂差异直接体现在图形与功能列表中。

功能与原厂相同但存档中存在显式覆盖时，按键视图按功能一致展示；动作视图保留覆盖信息。

### 编辑

支持给按钮添加或移除动作，也支持从动作的按键列表添加、更换或移除按键。两种入口编辑同一关系。添加功能时显示该动作已有按键、可编辑数量与上限；满额时禁用添加，并提示先移除或替换已有按键。容量来自真实可编辑槽，固定映射独立计算；手柄按动作注册数量展示。[绑定反馈设计图](binding-feedback.png) 定义移除项、满额提示和应用中状态。

移除按键表示解除该按钮—动作关系；若多个底层记录共同提供该关系，应处理所有相关记录，避免移除后依然生效。移除不能简单等同于删除覆盖，因为删除覆盖可能恢复原厂按键。

“恢复原厂默认”为独立操作。没有有效按键的动作显示“无绑定”，不显示三个意义不明的“默认”占位格。

## 全方案差异

“方案更改”位于工作区底部，横跨左右两栏，在按键视图和动作视图中均保留。它显示当前方案全部键鼠与全部手柄家族的变化，不随选中按键、设备或家族缩小范围。

| 比较方式 | 基准与用途 |
| --- | --- |
| 与修改前对比 | 对比磁盘上已保存的当前方案；应用后更新基准，列表清空。 |
| 与原厂对比 | 对比原厂默认；已保存的自定义仍保留在列表中。 |

每行显示设备及手柄家族、动作和可切换的绑定内容。默认按“新增 → 保留 → 移除”排列：新增带 `+`，待应用用黄色、已修改用蓝色；保留项使用普通文字；移除项带 `−`、灰色和删除线。默认没有模式标签或边框，不重复显示箭头、前后集合或逐行增减数字。全部解绑时显示“无绑定”，再列灰色移除项。

点击该行的绑定内容，或聚焦后按 Enter／空格，循环切换该行四种展示方式。模式在刷新、切换比较基准或视图后保留，并按方案、设备家族和动作分别记忆；不会创建草稿或写盘。

| 展示方式 | 内容与标识 |
| --- | --- |
| 绑定变化（默认） | 新增 → 保留 → 灰色移除，无模式标签和边框。 |
| 纯变化 | 仅新增、移除；蓝色细边框和“纯变化”方形标签。 |
| 纯结果 | 仅当前有效按键；保留项按基准顺序在前，新增项在后；青绿色细边框和“纯结果”方形标签。 |
| 原本 | 所选比较基准的按键集合；紫色细边框和“原本”方形标签。 |

悬浮详情同时显示原本、结果、当前展示方式及切换提示。模式边框颜色与黄／蓝的保存状态区分。[差异展示图](binding-diff-modes.png) 定义四态的内容和视觉层次。

总数只在标题处保留，按去重后的按键—功能关系统计，不按内部槽位统计。实际按键集合没有变化的动作不显示差异行。快速配置和恢复动作默认时，跳过按键集合不变的动作；恢复至已保存的按键集合会清除对应草稿，不产生多余的待应用标记。基准不完整时按已确认关系统计下限，不推算未知增减。原厂左键没有格挡，因此显式左键格挡即使与继承槽并存，也显示自定义并进入原厂差异；保存后新增其他非原厂键、移除或恢复这条关系，均独立更新徽标与计数。

快速配置名称突出主要操作效果，保留键、替换范围等补充信息放在说明中。展开下拉列表并悬浮具体条目时，在列表旁弹出缩小的键位图：灰色为原厂一致，蓝色为预设相对原厂的绑定变化，下方逐项展示原厂按键 → 预设结果，并显示颜色图例。键鼠与手柄使用相同颜色规则，以设备图和文字区分。预览以原厂布局套用该预设，不混入用户保存的自定义或草稿，不表达保存状态。浮窗不抢焦点、不遮挡选项，关闭列表即消失；主界面不插入预览横栏，悬浮与选择均不改变工作区布局。悬浮不选择配置、不修改草稿、不写入存档。

快速配置区域内使用三个同时可见的分段选项：“追加按键／替换按键／仅用预设”，可直接选择。首次使用默认选择“仅用预设”，之后记住玩家上次选择，重开程序也保留。预设选择器为主操作，三段选项以更小字号、更低高度和内容宽度在其下方排列，选中项使用轻底色与细酒红下划线；悬浮说明该方式的作用。“预设管理”只与上方选择器对齐。三段控件仅属于预设，不延伸到设备或绑定编辑区域。[套用方式设计图](quick-preset-modes.png) 定义两级控件的主次关系。

| 套用方式 | 对当前方案的影响 |
| --- | --- |
| 追加按键 | 普通绑定保留已有有效按键，加入预设按键；相同按键不重复。 |
| 替换按键 | 替换预设涉及动作的普通绑定。 |
| 仅用预设 | 将所含设备的普通绑定恢复原厂后套用预设。 |

含增强配置的预设在追加模式合并规则，其他模式替换所含设备的增强规则。脚本、返回值钩子及输入屏蔽等配置按实际计划处理，从预设管理选择载入后，在主页的载入确认中核对；普通绑定的范围不代表这些配置也只影响同一组动作。

普通绑定与增强规则修改当前方案；内置预设的手柄改动覆盖该方案各手柄家族，自定义预设按其明确保存的设备范围处理。选择预设即形成草稿，“应用更改”才写入。切换预设或套用方式均从同一份选择前状态重新计算，不叠加上次试选的效果；取消预设恢复该状态。普通模式追加时槽满则整次拒绝，增强模式可将支持的溢出绑定转换为增强规则；无法套用时指出动作与设备，保留原草稿。不同动作共用同一按键不算冲突，不自动移除。“恢复原厂”独立于套用方式，选中时禁用套用方式选择。

悬浮预览始终回答“这个预设相对原厂怎么改键”，不随套用方式或用户草稿改变；实际套用结果在主界面和底部“方案更改”中查看。

### 我的预设、分享与导出

快速配置列表按“内置预设／我的预设”分组，在选择器旁提供“预设管理”。管理窗口只依赖预设库：左侧为已收藏预设，右侧为分享码输入及预设内容、名称和分享操作。首次打开聚焦分享码输入框。粘贴后自动解析，或点击“粘贴”读取剪贴板。内置预设不进入可删除列表。

主页方案栏“保存为预设”提供独立命名和设备范围选择，保存当前方案相对原厂的普通绑定增减及增强配置，包含尚未应用的修改、纯解绑和各手柄家族的差异。管理窗口选中条目后展示完整预设内容，可改名、导出或复制分享码。复选框只用于批量删除，勾选其他条目保留当前详情。收藏、改名、删除只修改预设库。删除须确认名称。库保存在 `%LOCALAPPDATA%\PBZKeyForge\Presets`。

分享码是一行 `PBZ2:名称:内容`，保存稳定数字编号表示的原厂差异、基线编号和设备范围，以 Protobuf 序列化，比较原始与 DEFLATE 数据长度选较短者，再编码为无填充 Base64URL。名称中的冒号保留，最后一个冒号分隔内容。[格式与永久编号](../formats/preset-share.md) 定义维护规则。

“分享范围”下拉和复制分享码位于内容区下方，影响复制和导出的内容。可选择全部所含设备、仅键鼠、仅控制器或实际存在的手柄家族；没有多个手柄家族时不重复提供“仅控制器”。“导出预设”将该范围的分享码保存为 UTF-8 文本文件。管理窗口中的名称用于收藏或改名该预设。

分享码与已保存预设直接展示所含设备、动作、按键、触发方式和增强设置。普通绑定依预设声明的原厂基线还原，增强规则及配置从预设自身读取。预览内容与主页当前方案、草稿和载入方式无关。非法分享码清空旧结果并禁用载入。

点击“载入编辑器…”仅将预设返回主页。主页另开载入确认，显示编辑目标、载入方式和实际差分，确认后才形成草稿，再点击“应用更改”生效。取消载入确认保留原草稿。导入不要求先收藏，也不会自动创建库条目。只有键鼠的预设选择“仅用预设”时只重建键鼠；指定手柄家族同理。空差异仍保留范围，表示该范围恢复原厂。无法套用的预设不改变现有草稿。固定映射不占用可重绑槽，分享码不能移除固定映射。

导出 `.sav` 从当前读取的原文件克隆，仅合并当前方案的草稿；其他方案保留原文件内容，不带出其未应用修改。导出不清除草稿、不切换游戏采用的方案，也不允许覆盖当前源存档。手柄预设按家族名称匹配，本次更改标明实际影响的家族。无法确认原厂键的已修改动作不能生成差异预设，可通过导出游戏键位文件完整保留。

应用更改在后台执行，按钮显示转圈与“正在应用…”；期间禁用编辑、重复应用和关闭。完成后停止动画并显示结果，失败保留草稿、恢复操作供重试。游戏程序身份摘要在文件路径、长度和修改时间不变时复用，每次仍读取并核验已登记密钥和认证存档。

## 动作视图：动作与绑定记录

主表以动作为行，分为动作、原厂按键、绑定 1／2／3。动作配有独立图标；原厂按键在单独一列显示。绑定格直接显示具体按键；空槽显示弱化的“—”，状态由颜色圆点及悬浮详情表达。原始记录入口展示同槽多条记录和非标准槽；手柄家族选择同时约束主表、图形与原始记录编辑。绑定弹窗明确区分以下状态：

| 状态 | 展示示例 |
| --- | --- |
| 继承默认，且已确认该槽默认有键 | 默认 \| 右键 |
| 继承默认，且已确认该槽默认无键 | 默认 \| 无绑定 |
| 默认未确认 | 默认 \| 未确认 |
| 自定义绑定 | 具体按键 |
| 显式解绑 | 无绑定 |

地图槽 0 的默认选项显示“默认 \| M”，槽 2 显示“默认 \| Tab”，原厂按键列显示“M、Tab”。蹲伏的键鼠首列对应原始槽 1。不能把动作级默认键集合重复放到每个槽里。

影之武装长按的键鼠 Ctrl 属于固定 Hold 映射，计入动作原厂集合与按键功能数，并标注“固定映射”；保存覆盖不能移除这条输入，因此关系的更换与移除入口禁用。手柄长按有独立可重绑槽。

同槽多条记录、不同设备家族及其他不能用单个格子完整表达的受支持配置，应能查看其差异。动作视图不能为适应三格展示而丢弃底层信息。

没有可用槽的逻辑列显示“—”并禁用。手柄普通编辑仅使用具有原厂注册的槽，不创建方案激活时不会采用的额外家族条目；已有额外记录保留在原始记录入口。

## 两个视图共享的行为

- 编辑同一份状态和草稿，不维护两套独立配置。
- 任一视图修改后，另一视图立即反映对应结果。
- 切换视图不写盘、不重置、不丢草稿、不改变启用方案。
- 按键视图隐藏的信息完整保留；显示去重不等于合并、重排或重写底层槽位。
- 添加、更换、移除、显式解绑与恢复默认在两个视图中语义一致。
- 视图之外的保存、撤销、刷新和冲突处理继续使用同一套规则。

若某配置不能在按键视图中无损编辑，保留其状态并提供明确的动作视图入口，不静默改写。

## 配套功能

### 离线方案与手柄家族

没有游戏安装、存档或手柄时，使用内置原厂基线直接进入编辑。键鼠、Xbox、PlayStation 均可选择；家族选择器只在手柄页显示，切换方案按家族名称保持选择并重新绑定当前方案的记录。界面显示 PlayStation，存档使用游戏标准身份 `PS`。

离线页脚显示“离线编辑”，主操作为“导出键位文件”，不提供游戏方案激活。黄色状态称为“方案改动”；保存预设或导出不会把方案内容改回原厂。预设管理继续提供保存、范围分享和导入。打开实际存档后使用正常应用流程。仅浏览不向存档添加家族记录，修改的目标家族在输出时建立。

### 左右键攻防预设

预设名为“左轻右重，双键防御”，标识为 `mouse_guard`：

- 左键：轻攻击＋防御。
- 右键：重攻击＋防御。
- F：单独重攻击。

仅修改当前方案对应的轻攻击、重攻击、防御键鼠绑定。预设说明明确其替换范围，手柄、其他动作、其他方案和未知数据保持不变。按游戏实际映射语义生成必要记录，不因预设 helper 默认填满三槽而制造无意义的重复绑定。

### 明确解绑

键鼠和手柄均提供“无绑定”，与默认继承、清除覆盖和恢复默认区分。动作视图解绑单个槽不代表解绑整个动作；按键视图移除一个按键关系时，其他按键关系仍保留。

### 绑定弹窗

录入区域使用可聚焦的按键捕获控件，不出现文本输入光标、文本选区或文本框右键菜单。保留键盘、左右修饰键及鼠标按钮捕获。选择框中的按键文字正确居中，控件在项目支持的缩放下保持布局完整。

### 动作名称

简繁中文 `IA_Sense_Default` 均显示“澄心洞照”。相关文案和测试一致。

## 图稿与实现

[按键视图设计图](binding-perspectives.png) 定义同屏键鼠、右侧功能与底部全方案差异的布局。设备图及动作图标位于 `assets/ui/devices/`、`assets/ui/actions/`；程序内嵌透明资源，按实际 DPI 绘制。影之武装图标使用大斧。

`EditorSession` 持有全部绑定与草稿。`BindingRelations.cs` 投影当前、已保存与原厂关系；`KeyBindingView` 展示图形徽标及选中键的功能；`SchemeDiffView` 展示全方案差异。动作表及原始记录弹窗编辑相同记录。切换视图不做保存或状态迁移。

## 验证

新增文案覆盖 15 种语言。常规界面检查只运行简体中文；仅在针对性本地化测试时加 `--all-languages`，词典检查单独运行 `I18nTranslationTests`。`BindingViewsTests` 验证共享草稿、导航不写盘、重复记录和设备家族隔离；实际点击键盘及鼠标五键，验证保存、撤销、恢复和解绑至零时的徽标颜色；验证两种比较基准与跨设备总数、图外键换行，并输出常规和最小窗口截图。

`EditorUiTests --bindings-only` 覆盖明确解绑、默认继承、取消、键鼠捕获与左右修饰键。`MouseGuardPresetTests` 覆盖预设保留 F、保存重开和方案隔离。CLI 自检要求存档往返为 `roundtrip=IDENTICAL`。运行入口见 [本地验证](../../tests/README.md)。

## 已知限制

资源默认数据适用于 CL-301524。未知动作保留原始记录编辑能力，无法确认的默认值继续明确标注。Blob 保存共享 profile 的变化，设备归属由原厂注册决定；已注册手柄槽在家族激活时使用家族当前值，缺行回原厂值。

图形、文件保存与静态游戏证据不代替游戏内操作验证；组合技能的时序与实际出招效果未作游戏内实测。
