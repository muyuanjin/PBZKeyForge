# 键位增强

在主窗口左下开启“键位增强”，继续用原来的按键和动作入口编辑：点击按键后“添加功能”，或打开动作详情添加、修改、删除绑定。开关只暂存配置；点击“应用更改”后安装游戏 Mod，下次启动游戏时加载。首次安装、启停和卸载时需要退出游戏；新版 Mod 已随游戏加载后，绑定修改可以实时应用。

普通模式的单键保存到游戏存档的原生槽位。开启键位增强后，普通键位和增强规则都由当前方案的运行时配置承载，已登记且支持的玩法输入由统一调度执行。可以继续添加绑定，也可以给同一功能分别设置按下、短按、长按、组合键、连按和顺序输入。一键可以有多个功能，一个功能也可以有多个输入；它们在同一按键详情和动作详情中显示。

方案栏直接展开所有方案。普通模式编辑原生三个方案；增强模式使用独立方案，首次从原生三个方案复制键位，之后分别保存。紫色“＋”从当前方案复制新方案，旁边的“•••”可重命名和删除新增方案；正在使用的方案须先切走再删除。方案多时可左右滚动或从“更多方案”定位，新增与保存按钮始终可见。关闭增强后回到原生方案，再次开启时保留增强方案和编辑位置。完美防御无连点惩罚是独立选项。

点击方案标签只切换编辑对象。“应用到游戏”部署方案库并切换到选中方案；底栏及标签标记显示实际使用的方案。普通键位、复杂绑定、原生触发屏蔽和按键占用均归当前增强方案。功能选择中可添加切到指定方案、上一方案或下一方案的绑定；这些管理绑定在各方案间共用，关闭编辑器后仍可切换。切换会结束旧方案的持续输入，攻击、跳跃等仍按住的离散输入须松开后重新触发。

方案栏的“保存为预设”直接保存当前方案草稿，可输入新名称或选择已有预设并确认覆盖，无需先应用到游戏。可选择键鼠、手柄或两者；预设保存当前方案，ZIP 配置包保存整个方案库。

关闭增强后，普通单键仍优先编辑当前方案的存档绑定，即使之前留有实时覆盖也一样。直接打开停用的增强绑定进行修改，则继续编辑该增强草稿。编辑器的作用范围提示随实际保存位置变化；游戏启动或退出后，已经打开的编辑器也会更新提示。

## 编辑绑定

动作视图使用左侧分组树与右侧表格。“全部功能”与各分组并列，显示完整目录；每个分组显示所含功能数。增强模式首次打开动作视图或添加功能时默认浏览全部，普通模式默认浏览“普通模式动作”。后者严格对应普通模式已有的 21 个动作。

增强功能按用途组织：移动与身法、视角与锁定、攻击与处决、防御与闪避、武器、影之武装、饰品、交互与道具、场景移动与行船、界面操作；调试、测试与旧版输入放在末尾，已有自定义功能单独显示。同一用途下集中列出相关输入阶段和具体能力，例如防御与闪避包含完美格挡、架势、普通／持续／完美闪避、瞬身及其变体。武器内区分使用与切换、各武器的轻攻击、重攻击及特殊招式。药品集中包含普通、上半身和特殊场景用药；菜单、页签、跳过、QTE 和拍照归入界面操作。关闭增强时目录仍完整可浏览，需要增强的功能显示启用提示。

搜索名称、武器名、别名或代码可跨组查找，也可用空格分开多个词，按任意顺序组合武器、招式、奖励和技术名称。同一动作共享的每个游戏名称分别显示为一行，点击后保留所选名称，但底层仍只写入一个动作。表格对齐显示动作名称、原厂按键和当前绑定；点击绑定可直接修改，点击末列加号可添加，点击动作名称打开详情。

动作表可从已解析的 BulletData 显示攻击洞察：物理或元素伤害系数、削韧系数、原生条件分支的范围和时间轴攻击节点。系数和节点数也可参与搜索。这些数值描述动作资源，不是单次最终生命伤害，节点数也不等于实际命中次数；部分 BulletData 无法唯一解析时，提示会说明结果只含已解析资源。

额外动作详情中的关联普通动作可直接点击，旁边显示当前有效按键；返回后同步更新，不必关闭详情重新搜索。手柄编辑优先列出手柄按键，组合键可逐项添加，也支持混合设备输入。录制区域只接收键盘与鼠标，手柄按键需从列表选择。

小窗口会压缩顶部和组件说明，完整说明仍可在组件菜单及悬停提示中查看。没有差异时收起方案差异区；通过“更多 → 方案更改”可以切换与修改前或原厂的对比。

“移动与身法 → 移动方向与轴”集中列出向前、向后、向左、向右移动，原厂键为 WASD 和方向键；手柄优先显示摇杆移动。可直接修改某个原厂方向键，替换只拦截该按键，其他方向和同方向的备用键保留；添加绑定则保留原来的按键。四个方向已设好输出轴值，无需手填向量。同组保留键盘、摇杆和通用二维轴入口；冲刺、慢走、跳跃与下蹲各有分支。

持续按住角色移动、冲刺、行船方向或架势时，从地图、菜单、失焦或配置重载返回后会继续输入，无需松开重按。新增的连续视角、锁定目标轴，以及显式设为持续／轴触发的通用移动、攀爬和船只视角输入也保留该恢复行为。原厂带时序触发器的输入继续遵守自身触发条件；攻击、交互、慢走切换和点按防御等待新的按下。架势恢复不会额外触发完美防御，角色移动屏蔽也不会屏蔽独立架势或视角输入。

“收起武器”对应输入动作 `IA_ChangeArmed`，独立绑定时只能收起武器；“收/拔武器”对应技能 `Ability.UpperBody.Hun.ChangeArmed`。两项与“更换武器”分开显示，可搜索“收刀”“入鞘”或 `sheathe`。单独绑定默认按一次触发，游戏原有长按更换武器键的入口保留。

开启键位增强后，非战斗闪避在游戏允许走出边缘或允许跳跃时放开边缘保护，实体碰撞继续生效。保护例外仅用于闪避输入与当前闪避动作，单独行走保留原规则。跳跃与闪避共用按键时，动作仍由游戏原生规则决定。闪避结束、进入战斗、暂停、移动被屏蔽或关闭增强时恢复原有保护。独立瞬身在收刀状态下先拔出当前武器，再请求原生瞬身；解锁与冷却条件沿用游戏规则。

开启键位增强时，主窗口四周出现蓝紫色动态火焰；关闭后立即消失。火焰不拦截鼠标，切出窗口或最小化时暂停。界面特效随当前开关显示，底部“待应用／已生效”说明游戏 Mod 的应用状态。

运行时出错时，底部统一显示一条错误卡片。点击“查看详情”可滚动查看完整错误与调用堆栈、选择文字或“复制信息”；主窗口保留原有尺寸。出招失败与输入恢复失败一并保留，应用配置失败也不会遮掉运行时原因。心跳中断或游戏退出后仍可复制最后一次错误。关闭卡片后，同一错误不会随状态刷新反复弹出；重新应用配置恢复调度后，运行时错误自动清除。

在按键视图选中按键，点“添加功能”并选择目标。按 Ctrl / Shift 可多选，一次添加为同时执行的多个输出。普通功能、额外输入动作和能力都使用同一选择入口。需要键位增强的功能在关闭时显示为灰色，仍可添加、编辑和解绑，保存草稿不会自动开启执行。

选择能力时可设置“保留游戏原有触发方式”；“设置绑定”与动作视图使用相同的复选框。它控制当前方案中该能力的原生触发方式，修改后适用于该能力的所有绑定。批量选择的原有设置不一致时显示为半选，直接添加会保留各自设置。已添加的绑定可点击卡片或旁边的“修改”重新打开设置，每条绑定分别编辑。

功能选择提供全部目录及同一套用途分类，可按分类浏览或跨组搜索；普通动作保留独立入口。额外功能同时显示名称和技术代码，可搜索原生名称、代码和别名，例如“瞬身”或 `SpecialDash`。目录含 98 个 InputAction 和 227 个可用通用能力，另提供 4 个移动方向入口及具体招式。九条没有能力实现的原始输入路线保留审计记录，见[通用入口核查](generic-ability-activation-audit.md)。能对应原厂招式的名称沿用游戏文本及 15 种原厂译文；共用招式不归于单把武器，同名的独立阶段保留短段码。输入名称区分点按／持续／长按、方向和设备。[完整名称与资源依据](key-enhancement-action-names.md) 可逐项查阅。

额外输入动作的原厂列按当前设备显示资源中的输入来源；“未添加独立绑定”只表示尚未为该入口新增绑定。经由普通动作设置的按键仍从对应普通入口编辑，动作详情会显示关联入口。

普通改键按可改绑名称定位。Esc、触板手势和场景固定输入保留各自来源，不随同名 InputAction 的普通绑定一起改写。

目录输入动作沿用当前设备的真实映射触发器与修饰器，保留点按、松开和长按的原生语义。运行时的组合依赖优先于默认模板；保留原生执行的管线不会额外注入同一动作。没有映射来源的目录动作默认按下触发一次。高级自定义输出可用 `NativePipeline: false` 显式选择直接注入，并保留自定义触发器与持续输入。

交互等场景动作只在游戏启用对应输入场景时参与调度。场景退出后暂停该动作的绑定，其他功能继续执行；场景重新启用后自动恢复。恢复时仍按住的交互键须松开再按，避免误触。

增强调度的优化范围、性能基准和回归覆盖见[运行时性能](key-enhancement-performance.md)。

完整招式可直接添加普通绑定，自动完成原生蓄力、备弹或连招所需的准备，保留装备、解锁、资源、目标与动作状态条件。默认和“按下时”绑定均在按住期间持续请求，松开停止后续出招；短按、松开时等单次触发只请求一次。例如「天玄青铜剑 · 重攻击 · 蓄力 · 释放」（`BHold · Release2`）只需一条普通绑定，无需额外绑定持续重攻击。已接入的招式与逐装备复查范围见[完整招式](complete-moves.md)。

直接能力的普通按键绑定也支持按住循环出招，例如斩马刀的亡命蓄斩；游戏仍决定当前装备、资源和动作状态是否允许发动。显式选择“按下时”可设为单次请求，“按住连发”可自行指定请求间隔。

战斗绑定设置提供伤害倍率、前摇速度倍率和后摇速度倍率，默认均为 1。前后摇可分别设为 0.1–10 倍，数值越大阶段越短；攻击阶段保留原速。资源选项注明精纯杀气、杀气或影之武装弹量，可按绑定选择绕过。设置随复制、撤销、预设分享和 ZIP 配置包保存；范围和实机验证状态见[资源与动作倍率](complete-moves.md#资源与动作倍率)。

“绕过限制”独立于资源选项，可分别选择装备、修行解锁、地面／空中、架势／移动状态、前驱动作和招式冷却。装备、拔刀状态和持续输入按真实原生流程准备，蓄力品质与目标实例保留实际状态，见[招式限制与原生准备](move-restrictions.md)。

打开动作详情可以查看它的全部绑定，逐条修改、解绑或停用，也可以继续添加。按键详情同样逐条显示绑定，同一动作的短按和组合长按分别操作；停用的绑定保留原有设置，可直接重新启用。编辑窗口提供“解绑”；选择功能时可点“设置绑定…”配置触发方式后添加。组合输入要求按键同时成立，顺序输入按指定次序识别。多输出会同时执行，顺序输入不会把输出变成延迟宏。时长、次数和启用状态等修改也计入差异预览。

动作详情逐条说明绑定来源、应用后的执行规划，以及原生执行拦截、关系共存和按键消耗规则。按键详情与表格悬停也显示归属。键位增强开关的悬停说明列出具体未覆盖来源；这些说明表示当前草稿应用后的规划，安装状态仍由底部的待应用／已生效信息单独说明。

绑定行的“…”可将现有输入与触发设置复制给其他动作；按键详情的“整键操作…”可移动或交换整键功能，包括 WASD 方向。复制、移动与全局重置均可撤销。

“更多设置”可调整绑定优先级、启用状态、占用哪些按键以及输出方向和倍率。组合输入可只占用其中部分键，例如 LB＋A 只占用 A，保留 LB 原来的防御。顺序输入的每一步也可以是组合键，可以直接连续录制，也可通过列表添加、修改和调整次序。轴输入提供正负方向，脚本监视列表也包括轴。同键短按与长按使用共用的时间边界和占用组，两种分支均可触发。已有非默认高级设置会在入口显示标记，悬停可查看摘要。

要保留 RB 闪避，并把瞬身改到 LB＋A，在动作视图搜索“瞬身”，打开 `Ability.Action.Hun.SpecialDash`，添加 LB＋A 绑定，并选择“替换游戏原有触发方式”。这会同时屏蔽普通瞬身和防御起始瞬身的原生组合入口，RB 的闪避绑定保留。也可在动作详情取消“保留游戏原有触发方式”。需要阻止组合时同时跳跃，可在“更多设置”中只占用 A。恢复原厂会恢复原有触发方式并移除该动作的自定义绑定。

新增绑定保留原来的功能。修改或删除一条绑定只作用于该关系。统一调度接手的原生关系会拦截原生执行以避免重复触发；未设置按键消耗时，同键的其他关系仍可参与调度。消耗规则控制哪些物理键暂时不再提供给其他关系。多个输入指向同一 InputAction 时仍共享游戏动作本身的状态。

主窗口“更多 → 自定义功能与返回值…”可直接管理全局功能与 hook，不必先选按键。选择窗口的“添加自定义功能”也可配置函数、事件、属性、返回值 hook 和脚本。布尔值、数字、文本与对象使用对应控件；函数参数、事件数据及属性值支持递归编辑结构和数组。需要自定义条件或返回表达式时再填写 Lua。

已有自定义功能在动作详情点“修改功能”编辑参数、目标和值，所有指向该功能的绑定保留。解绑最后一条输入后，功能仍保留，可继续修改或重新添加绑定；“删除功能”移除功能定义及其绑定。功能定义随预设、分享码和 ZIP 配置保存。输入的启用条件在绑定窗口“更多设置”里选择“游戏中”“游戏前台”或“未暂停”。选择“自定义脚本触发”后可填写识别器，并勾选脚本额外读取的按键；这些监视键也可单独设置占用。切换触发方式会清除不再使用的步骤、轴或脚本监视条件，改键时占用选择随输入更新。

运行时保留游戏输入上下文，逐条判断当前映射的执行归属。已登记且支持的玩法映射交由统一调度，其原生按键入口临时屏蔽；域外或不支持的映射保留游戏执行。每个输入来源保留原生触发器与修饰器的配置，并使用独立实例处理状态，不能用复制出的映射数量推断覆盖完整。组合键结束后，被消耗的键保持屏蔽直到实际松开。

输入处理从界面、暂停或前后台切换恢复时，只恢复符合持续条件的键盘移动、摇杆移动与冲刺。恢复时仍按住的攻击、跳跃等动作不会被当作一次新按下，需松开后再触发。菜单、文本输入和游戏自身的使用条件继续由游戏处理。

## 防御派生与连续攻击

“点按防御”和“持续架势”可以在增强目录中分别绑定。独立点按防御使用短促的原生防御输入，下一帧释放；按住时持续追加点按，保留原生防御窗口与防反，但不提供武技派生使用的持续架势资格。独立持续架势跟随按键保持与松开，可与攻击组合释放符合当前武器及状态条件的架势派生。普通“架势／格挡”保留原厂点防与长按架势行为。

开启键位增强后，在功能目录分别搜索 `IA_Deflect`（点按防御）与 `IA_Stance`（持续架势），为它们设置不同按键，并移除点防键上原有的普通“架势／格挡”。保留普通轻攻击与重攻击绑定，点击“应用更改”；连接实时编辑时可直接应用到游戏。更新增强脚本需先退出游戏并应用，再启动游戏。

只按点防键再攻击时，攻击按普通轻重击资格处理；按住独立架势键再攻击时，保留武技派生资格。两种防御同时按下时，独立架势仍生效；松开架势键、仅留下点防后，点防不会继续维持武技资格。同一键仍绑定普通“架势／格挡”时，该原厂绑定也会提供架势资格。

要让同一个键兼顾重击和点防，在重攻击键上添加“点按防御”，并移除该键原有的普通“架势／格挡”。按下时保留普通重击输入，同时开启原生点防窗口；受到攻击时按游戏原有条件判定防御，不会仅因点防转成架势组合武技。同键绑定普通“架势／格挡”和重攻击则保留原厂武技派生。轻攻击也遵守相同区别，成功防御后的原生追击继续保留。

需要明确指定攻击时，可为目录中的具体能力或完整招式设置独立按键或组合键。组合键可只占用攻击键，保留修饰键的防御功能；具体招式继续遵守自己的装备、解锁与状态条件。

要按住连续轻击或重击，同时保留原攻击键的蓄力，可另选一个空闲按键，在功能目录搜索 `IA_AttackL_Press` 或 `IA_AttackH_Press`，添加“按住连发”绑定并设置间隔。这条额外绑定只重复“按下”输入，原攻击键仍保留持续及长按输入。若使用修饰键加原攻击键的组合，应在“更多设置”中只占用攻击键，隔开连发与原生长按。

### 已知限制

当前没有按武器自动切换连发与蓄力的选项，两种操作需使用不同按键或组合输入。直接为普通“轻攻击／重攻击”设置连发，会重复该动作包含的点按、持续和长按输入阶段。连发间隔只是请求间隔，实际能否衔接、是否进入防御派生及招式费用仍由当前武器和游戏状态决定。防御输入与连续攻击已通过本地调度测试，实际战斗效果尚需游戏内核对。

## 应用、关闭与恢复

开启、关闭和绑定修改都随“应用更改”一起保存。关闭并应用通过 UE4SS 的 `mods.txt` 停用本工具 Mod，保留绑定配置。若 UE4SS 由本工具安装且没有其他 Mod 使用，会同时停载代理，下次启动游戏不加载 UE4SS；再次开启时恢复。用户原有的加载器和共享加载器保留。游戏运行时可继续编辑草稿；已连接新版 Mod 时，绑定修改使用实时应用。

模式关闭时，文件残缺不会自动产生待修复更改。开启后才检查安装并在应用时补齐。安装记录用于维护本工具管理的文件；未知文件或被修改的运行脚本会保留并报告冲突。存档保存成功而 Mod 失败时，界面分别报告结果，保留未完成意图，重试只处理剩余项。

配置源位于 `platform/steam/ue4ss/Mods/PBZInputRouter/configuration.json`，`Scripts/router-config.lua` 由它生成。配置被外部修改且本地仍有草稿时，保留草稿并提示重新加载。已有 UE4SS 的公共加载器、设置和签名保持原样；启用列表只修改或追加 `PBZInputRouter` 项，其他 Mod 的内容及顺序保留。支持配置中的自定义 Mod 目录和控制列表。

程序更新后，退出游戏并点击“应用更改”即可更新已登记的增强脚本，保留全部增强方案和绑定。旧版中已移除的脚本会一并清理。

完全移除使用“键位增强旁的 … → 完整卸载键位增强”，再点“应用更改”。卸载移除本工具的脚本、运行配置和启用项；由本工具安装且未修改的加载器文件，在没有其他 Mod 使用时一并移除。原有共享加载器、仍被其他 Mod 使用的文件及未知修改会保留，结果中列出保留项。

每次应用和实时应用都会将完整配置保存在 Mod 目录外的 `platform/steam/PBZKeyForge_KeyEnhancement.configuration.json`。卸载或手动删除 Mod 目录后，重新打开工具会读取这份配置并保持增强关闭；再次开启并应用即可恢复方案和绑定。卸载时也会保留已有配置。若要彻底清除个人配置，在卸载后删除这份文件。

按键详情中，已移除功能可直接点击“恢复原厂”。增强模式的单条恢复、整键恢复和预设追加更新当前方案的运行时绑定，保留其他按键、另一设备和其他方案。扳机恢复同时处理按钮与轴。普通模式维持原生槽位限制，恢复失败时普通绑定和增强规则均保持不变。“恢复全部原厂”同时恢复普通绑定、清除增强方案、自定义功能定义和原有操作屏蔽及返回值设置，并关闭键位增强。

离线同样使用按键和动作入口编辑。导出的 ZIP 配置包含 `.sav`、`key-enhancement.json`、`router-config.lua`、选中方案及默认映射版本。通过“选择存档”打开 ZIP 可导入为离线方案，保留普通绑定和复杂规则，再继续编辑或导出；导入不会安装到游戏。无效配置包不会替换当前编辑状态。

方案栏的“保存为预设”保存当前选中方案的完整草稿，可输入新名称或选择已有用户预设并确认覆盖，也可选择键鼠／手柄范围。预设及分享码只包含当前方案，方案库与共用切换绑定通过完整配置导出保留。套用含增强配置的预设时，普通绑定按所选的替换／追加方式处理，追加模式合并当前方案内容，替换或仅用预设模式替换所含设备的增强绑定，保留范围之外设备的独立绑定；能力屏蔽随当前方案更新，脚本、返回值设置和功能定义为安装级配置，范围之外绑定所需的功能定义保留，定义冲突时拒绝套用。仅分享键鼠时排除手柄及混合设备规则，反之亦然；无设备归属的能力屏蔽仍保留在当前方案，自定义定义、全局脚本和返回值设置随预设携带。预览会提示配置范围。导出这类预设使用 ZIP，以保留普通绑定和增强规则。普通分享码格式保持不变。增强分享码使用省略默认值的二进制格式，常用按键和游戏目标使用固定编号，按实际长度选择是否压缩。

## 实时编辑与游戏伴随窗口

先关闭游戏，应用新版键位增强，再启动游戏并进入场景。运行中的 Mod 会向程序报告连接状态；连接后右上角显示绿色 **实时编辑已连接**，按钮变为绿色 **应用到游戏 · 无需重启**。编辑仍先进入草稿，点击按钮后才整组发送，等待游戏确认，再持久保存配置；避免选择按键、录制组合或填写脚本时立即影响游戏。应用中编辑控件暂时锁定，防止覆盖尚未完成的新修改。

增强模式的普通绑定写入当前方案的 `NativeBindings`，不写 `EnhancedInputUserSettings.sav` 或 `PBZSharedSetting.sav`。每套方案保存完整普通键位和增强规则，切换不改变原生方案选择；关闭增强后继续使用原存档绑定。普通单键、已覆盖的玩法绑定和高级规则走同一个实时配置入口。

增强方案可直接实时切换，实际使用身份由 Mod 回报。原生方案启用、首次安装、关闭、卸载、更新加载器、资源 Mod 与全局重置仍要求退出游戏。更新运行脚本同样需要退出游戏并应用，再重新启动。仅修改绑定时不会检查或替换加载器。

增强方案的实时发送独立于磁盘中的原生方案选择，运行时收到整套配置后先验证再确认。增强模式不开放原始存档记录编辑。普通模式仍按原生方案和手柄家族编辑，写盘前重新认证并遵循存档保护流程。

动作详情中的原有关闭按钮会变为“应用并返回游戏”；直接修改一条绑定时，确认按钮也执行同一操作。游戏确认后收起窗口，保留当前编辑位置。再次呼出可以继续调整，Ctrl+Z 或主窗口“撤销更改”可撤销已应用的键位，再次应用后送回游戏。详情中的“关闭”只回主窗口，未应用的草稿继续保留。

组件更改与键位草稿分别显示。游戏运行时可以先应用键位，组件启停、卸载及资源 Mod 意图留到退出游戏后处理。关闭程序或更换存档时，窗口明确提供“应用并继续／导出并继续”“放弃更改”“继续编辑”；应用失败或仍有待处理项时不会自动退出。

“更多 → 恢复实时键位原厂”仅恢复键鼠和当前所选手柄类型的普通输入，清除增强绑定、组合及屏蔽；保留组件开关、自定义功能定义、脚本与 hook。操作先进入可撤销草稿，应用后无需重启，也不改原存档。CLI 的 `restore-bindings` 使用相同规划。

录制框支持键鼠、XInput 手柄及 PlayStation HID 输入；同时按下可录成组合。选择轴输入后，推动摇杆或扳机自动填写轴及方向；仍可从列表选择 UE 键名。录制前已经按住的手柄键不会意外加入新绑定。

**Ctrl+Alt+K** 在游戏与同一套编辑界面间呼出或收起置顶窗口，再按一次收起并把焦点交还原窗口。“更多 → 游戏伴随窗口”提供相同入口。录制输入时暂停此全局快捷键，让该组合也可以作为游戏绑定录入。窗口化或无边框模式适合保留游戏画面；独占全屏是否最小化由游戏和 Windows 决定。这是主程序的伴随窗口，不是另一套 UE4SS 内嵌界面。

“更多 → 伴随窗口快捷键”可关闭或开启此全局快捷键，选择会保存。启用的游戏绑定或待应用草稿使用 Ctrl+Alt+K 时，伴随窗口快捷键自动暂停并提示，避免抢走游戏输入。移除冲突并应用后可自动恢复；取消录制不会改变该偏好。

连接存在时，界面会分别显示调度正常、运行时关闭或暂停及其原因。暂停后仍可通过“应用到游戏”重新发送配置重试，无需额外制造一次编辑；如果输入管线仍不可用，会继续报告暂停。加载或游戏暂停响应导致心跳过期时，显示黄色 **实时编辑 · 等待游戏响应**，暂时停用应用按钮，继续保留编辑草稿。游戏恢复响应后自动回到已连接状态，可继续应用。

从未收到 Mod 信号时显示“实时编辑未连接”。点击右上角运行状态可查看连接说明、Mod 路径、UE4SS 日志位置及状态文件。错误提示卡关闭后，底栏保留“应用未完成 · 点击查看详情”，完整原因随时可重新打开。

游戏拒绝配置、配置已被外部更改或等待确认超时时，草稿保留。超时请求会取消，避免游戏恢复运行后延迟应用。游戏接受后若持久保存失败，会恢复先前配置；回滚未完成会明确报告，需要重新检查状态。持久配置的原内容备份到游戏目录外的程序备份目录。

应用错误在编辑区上方以紧凑黄色提示卡显示，背景缓慢呼吸；底栏不重复错误。“查看详情”打开可调整大小的完整信息窗口，可滚动并复制。安装冲突包含具体文件路径。两个组件各自的“…”菜单提供使用说明；键位增强菜单中的“火焰特效”只修改外观。

**AI / CLI** 将用户说明与给 Agent 的提示词分开显示。“复制提示词”只复制给 Agent 的内容，包含实际程序目录、存档、方案、设备、运行状态和 CLI 命令。有未应用编辑或离线配置时，先导出包含当前草稿的临时 ZIP 供 Agent 编辑，保留原窗口草稿；Agent 输出的新 ZIP 可在 GUI 打开。见 [CLI 文档](cli.md)。

## 构建依赖

本地构建与 GitHub Actions 均使用 `build/ue4ss-sources.json` 中 `Bundled` 固定的 KintaroModding/ue4ss PBZ 发布包，下载后嵌入程序。仓库不保存加载器二进制。缓存位于 `%LOCALAPPDATA%\PBZKeyForge\cache\ue4ss-build`，按资源编号与更新时间命名；命中有效缓存时不访问网络，未命中时只下载固定版本，失败则终止构建。Actions 同样缓存该目录。Actions 使用 `GITHUB_TOKEN`，本地公开下载不需要凭据。

维护者可显式更新构建使用的版本：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File build\download-ue4ss.ps1 -OutputDirectory dist -UpdatePinnedRelease
```

该命令查询最新正式 PBZ 发布包，成功下载后更新 `Bundled`。确认安装测试与对应游戏兼容性后，将版本配置随源码一起提交。程序内的“检查 / 更新 UE4SS”独立查询最新版，不受构建固定版本限制。

维护开发、游戏更新适配或发布前，运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File build\check-runtime-updates.ps1`。它同时查询 UE4SS 正式 PBZ 包和 Steam 公共构建；普通开发可复用 24 小时内的成功观察，本机游戏构建改变时重新查询。用户反馈游戏更新或加载失败时加 `-Force`；发布使用 `-Release` 强制取得当前信息，发现未处理变化或查询失败时终止发布。普通离线构建仍直接使用固定包，不要求该查询成功。

定时工作流每六小时检查更新，发现变化后准备候选包、运行安装回归，并创建或更新一个草稿 PR。运行验证与兼容性记录由后续适配任务完成，见[更新与适配](../skills/phantom-blade-zero-save-modding/references/runtime-updates.md)。工作流提交到默认分支后生效；仓库需允许 GitHub Actions 创建 PR。草稿提醒不会自行启动 agent。

## 运行环境

编辑器使用 Windows 10/11 自带的 .NET Framework。键位增强需要 x64 环境及 [Microsoft Visual C++ v14 x64 运行库](https://aka.ms/vc14/vc_redist.x64.exe)；仅安装 x86 版不足以加载 x64 UE4SS。Steam 通常已安装游戏前置组件，但旧版运行库可能缺少 UE4SS 使用的新入口。

启用和更新加载器前会读取目标 UE4SS 与代理的导入表，检查其所需 Visual C++ DLL 和入口能否加载；检查失败时在修改安装文件前停止，并显示修复下载地址及具体文件或入口。游戏程序目录中的同名 DLL 优先于系统运行库，若提示指向该目录，还需检查该文件的来源和版本。关闭、卸载、普通改键和离线导出不受此检查限制。检查通过表示这些依赖可用，游戏版本和其他 Mod 的兼容性仍按各自规则判断。

安装和更新需要游戏目录的写权限。程序以普通用户权限运行；受限目录中的权限错误会显示具体原因。

发布程序未做 Authenticode 签名，下载后可能出现 SmartScreen 提示。请从项目发布页获取完整包并核对发布来源。

键位增强旁的“…”提供火焰特效设置、打开文件位置、检查 / 更新 UE4SS 和卸载。完美防御旁的“…”提供说明、文件位置和卸载，卸载随“应用更改”执行。

## UE4SS 更新

首次开启键位增强且尚未安装加载器时，“应用更改”会先检查最新 PBZ 发行包。日常修改绑定直接使用已安装的运行时；需要更新时，通过键位增强旁的“…”主动检查。发现新版会显示当前版本、目标版本并询问是否更新；无法识别已有版本时明确显示为未识别，由玩家选择是否改用 Kintaro。选择“暂不更新”继续使用原版本。检查失败时可以使用原有或内嵌版本继续、选择本地 ZIP，或取消此次应用。关闭、卸载和纯离线导出不要求检查更新。

自动下载依次尝试 GitHub、`ghfast.top`、`gh-proxy.com`，可复用已经下载的对应发行包。发布信息通过 GitHub API 获取，失败后尝试代理 API。线路是公共服务，无法保证所有地区与运营商均能连接；也可打开发布页自行下载 PBZ 版 ZIP，再用“选择本地 ZIP…”导入。

更新只替换加载器核心文件；本工具安装且未改动的配套文件随包更新。已有 `Mods`、启用列表、`UE4SS-settings.ini`、第三方签名及其他自定义文件保留。原加载器及本工具的归属记录备份到程序备份目录，替换失败会回滚。第三方加载器必须经玩家确认才会替换，其文件不会因此变成本工具卸载时可删除的文件。

## 已知问题

- 静态资源来自 Steam CL-302256 / UE 5.7.4。统一执行归属、原生管线、关系共存、消耗释放和移动恢复通过本地模拟测试，尚未完成这套运行时方案的实机验证。
- 鼠标视角增量（`Mouse2D` / `MouseX` / `MouseY`）、滚轮（`MouseScrollUp` / `MouseScrollDown`）、触板手势（`PBZ_Touchpad_*`）及复杂组合依赖／阻断触发器（`InputTriggerChordAction` / `InputTriggerChordBlocker`）保留原生执行。原生时序触发器仅在已验证取消后能正确复位时纳入调度；`RepeatedTap`、`Combo` 和未验证的自定义触发器保留游戏执行，运行时归属日志列出具体来源与原因。
- 手柄调度可读取 UE 原始输入值；独立物理采样及中断后的物理恢复尚未覆盖。菜单和文本输入属于游戏原生处理范围，不计作键位增强的玩法覆盖缺陷。
- 键盘和鼠标按钮按帧读取 `GetAsyncKeyState` 高位电平。一次按下和释放若全部发生在两次采样之间，短点击可能漏采，不能据此视为已覆盖全部物理事件。
- 能力仍受角色资格、资源、动作状态和参数限制。独立点防不提供武技派生的持续架势资格；具体武器的攻击衔接与防反效果仍需游戏内核对。
- 调度执行的额外绑定没有固定槽位上限，实际开销随每帧处理量增长。保留游戏执行的映射可直接修改运行时按键，蹲伏冷却、切换武器的组合触发器等原生管线支持普通键位的实时应用；自定义增强输出仍须有可调度管线。场景尚未启用的动作等待场景返回；已启用动作的设备身份无法确定或键数超出可用原生行时，整组拒绝并说明原因。同一映射中的调度管线与保留原生管线分别检查容量。
- 新增能力绑定默认保留原有组合，需在动作详情取消“保留游戏原有触发方式”才屏蔽它。运行时屏蔽已完成静态资源核对及模拟恢复测试，尚未实机验证；[架势瞬身资源补丁](../prototype/input-router/special-dash.md)是另一种独立方案。
- 已有加载器按实际配置复用，支持其标准 UE4SS Lua 接口；未知构建的运行效果仍需在对应游戏中验证。缺少帧调度接口时运行时保留游戏原生输入并记录原因。
- 安装状态与运行连接分别显示；实时应用成功表示 Mod 接受配置，不能替代对应动作的实机效果验证。
- 独占加载器停载期间，另装其他 Mod 后需要在本工具中应用一次或卸载键位增强以恢复代理；本工具关闭时无法响应外部安装操作。
