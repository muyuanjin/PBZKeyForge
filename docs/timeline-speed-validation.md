# 动画调速与激活生命周期

前摇与后摇倍率属于本次实际启动的动作。普通动作、不同绑定、旧动作与新动作分别保留自己的初始速率和参数。

## 蓄力阶段与原生自动播放

亡命蓄斩的实际蓄力超出了原生 `Action Phase.Start`：`GA_Hun_ZhanMa_DB.Main` 在 0.2 秒后进入 Act，但首个弹体动作直到 1.348594904 秒才开始。只按 Start 调速会留下原速蓄力；该能力按真实首个攻击动作确定前摇结束，攻击、两击间隔与后摇各自结算速度。

原生 `bAutoPlay` 激活直接调用 C++ 播放函数，初始速率为 1，不经过 Lua 的反射播放钩子。自动播放以该原生初始值作为基准；显式播放保留实际传入的速率，不能统一覆盖成 1。其他未取得初始速率的时间线保持原值。

## 独立蓄力计时

天玄青铜剑与白山风雷剑 `B_Hold` 的 `Main` 均为准备时间线，整段使用前摇倍率。释放攻击改用各自时间线的原生阶段，后摇继续使用独立倍率。两招原生 0.5 秒持键等待按本次前摇倍率缩短或延长：2 倍为 0.25 秒，0.5 倍为 1 秒；完整释放配方仍通过原入口执行。

白山风雷剑还按独立 Tick 推进充能。原生桥在指定实例的原 `OnTick` 执行前缩放反射 `DeltaTime` 参数，使杀气消耗和雷势累积同步推进，保留原有 350 与 0.34 系数及两者比例。回调结束后还原输入参数，其他能力、普通原生操作和无关 Tick 保持原值。失败请求恢复之前的实例设置；结束、取消或停止增强时清理倍率。

## 活跃实例重新出招

原速亡命蓄斩后紧接增强绑定时，原生请求可以在一次调用中结束旧动作并启动新动作，同时复用同一个能力实例。请求前后 `bIsActive` 都可能为 true，不能据此认定旧动作仍在继续。

调参记录在请求前保存当前时间线任务；成功请求替换了该任务时，新动作取得本次绑定的参数。嵌套调用共同指向该次新任务，避免外层覆盖内层已经取得的初始速率。失败请求或未替换任务的请求保留原动作参数；原生能力资格与取消窗口继续决定能否出招。

按名称播放的 `PlayTimelineByName` 同样记录新动作的初始速率，即使请求开始时旧动作没有调参记录。否则非自动播放时间线可能因缺少基准而跳过调速。

增强动作后直接使用原生操作，也以新任务区分下一次执行。成功更换任务后清除旧调参，恢复普通动作的速度、费用和伤害；已发射弹体保留发射时的伤害倍率。失败请求或未更换任务时继续保留当前增强动作。原生操作只检查已有调参实例，无需扫描全部已授予能力。

## 已知限制

其他独立输入等待、Tick 或资源累积须按实际用途核对，不统一缩放。白山风雷剑加速后每个真实帧推进更多充能，最后一帧的消耗与充能量仍按原 Tick 结算粒度决定。

没有 LegoAbility 时间线的动作不适用该调速机制。已收录的饰品鬼火发射属于此类，其完整招式标记为 `activeCallbackOnly`，界面隐藏前后摇速度设置。非自动播放时间线若没有捕获到初始速度，运行时也会保留原值。公共入口与 36 个战技阶段的回归通过，其他招式和蓄力过程仍按各自资源与生命周期证据确定支持范围。

青铜剑、白山风雷剑的独立计时及其余招式的上述结论来自配置、资源与生命周期测试，未逐个进行实机动画验收。基于任务更换的重启识别发生在原生激活返回后，不能据此证明重启调用内部已发生的同步费用或瞬时伤害也取得了新参数。
